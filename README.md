# ACol 电池

<img src="src/main/assets/webroot/assets/acol-icon.png" width="88" alt="ACol 电池图标">

**电池信息、充放电曲线记录、耗电统计与预估、截止电压调整。**

ACol 电池是一款面向兼容 OPLUS 电池接口设备的本地电池监测与分析应用，主要适用于 ColorOS 与 realme UI。应用通过 root 读取电量计、充电驱动及系统运行信息，由独立后台持续保存充放电过程，并提供应用耗电分摊、续航预估和游戏性能观察。

实时读数用于查看当前状态，历史曲线用于分析过程，耗电统计用于衡量一段使用中的容量和能量消耗。前台退出后，记录后台仍可独立运行；数据与配置保存在设备本地。

[下载安装包与源码](https://github.com/AstriaFR/ACol-Battery/releases/latest)

## 功能概览

| 功能 | 内容 |
| --- | --- |
| 实时状态 | 集中查看电量百分比、剩余容量、电流、电压、温度和电池侧功率 |
| 电池信息 | 查看容量、健康度、循环计数、电芯读数及电池资料，结合厂商参数分析容量补偿与估计锁容容量 |
| 充电记录 | 保存电流、电压、功率、容量、电量和温度曲线，识别尾充完成并记录循环计数 |
| 普通放电记录 | 按屏幕状态采样，展示容量、电量、电压和区间平均功耗 |
| 游戏模式 | 独立配置功耗与性能采样间隔，记录瞬时功耗、电池温度、画面帧率、CPU 各簇及 GPU 的频率与使用率 |
| 耗电分析 | 汇总亮屏、息屏消耗，并按前台使用时段分摊应用耗电 |
| 续航预估 | 根据当前容量、电压关系模型及记录中的亮屏平均功率，估算剩余能量和亮屏时长 |
| 截止电压调整 | 在驱动支持时分别读取、设置软件关机电压与电量计截止电压，支持解除手动覆盖 |
| 历史管理 | 按充放电类型筛选记录，配置容量/百分比的大项与小项显示、自动隐藏与自动删除策略 |

## 运行环境

应用要求 Android 15 及以上、ARM64 设备，并使用能够向应用授予 root 权限的环境。应用通过通用 `su` 接入 KernelSU、Magisk 和 APatch，使用 root 框架的开机脚本机制恢复后台，不依赖特定框架的解压工具。初始化会检查 root 权限、电池接口、原生采样定时器及屏幕状态监听能力。Magisk、APatch 的真机兼容性仍需进一步验证。

兼容性取决于底层接口。记录功能需要 OPLUS 电量计的剩余容量读数、系统电量百分比，以及可识别的外部供电状态。独立电芯电压、电池资料、性能指标和截止电压调整分别依赖相应驱动，不一定在所有设备上齐全。

首次运行时，应用完成授权、接口检查和独立后台部署；后续打开优先连接已有运行环境。必要条件不满足时显示具体原因，可选接口缺失则使相应字段或操作不可用。仅系统名称相同，不能保证所有底层功能一致。

## 实时状态与电池信息

首页将主要实时读数集中展示。电流与功率保留充放电方向，电流单位按数值自动换算。双电芯设备的首页电压采用两芯均压；电池信息页和记录详情可以分别查看驱动提供的电芯读数。

### 数据来源与单双电芯口径

剩余容量来自 OPLUS 电量计的 `battery_rm`，系统电量百分比来自电池电源节点。电压、电流和温度优先解析底层 `bcc_parms` 响应；缺少有效数据时，分别尝试 Android 电池广播、`BatteryManager` 或相应系统电源节点，并统一单位与电流方向。

后台从 `aging_ffc_data` 识别电芯数量并保存识别结果。尚未识别时继续重试，依赖电芯数量的读数与计算保持缺失。

| 电芯结构 | 电压与瞬时功率计算 |
| --- | --- |
| 单电芯 | 使用单芯电压和原始电流计算功率 |
| 双电芯 | 保留两芯独立读数，以平均电压和补偿后的电流计算功率；电流按支持的 OPLUS 数据口径乘以 2 |

双电芯计算等价于原始电流乘两芯总电压。系统回退若提供整组电压，会先折算到平均电芯电压口径；只能取得整体电压时，不生成虚构的独立电芯数据。

补偿依据当前支持的 OPLUS 接口格式，不能仅凭设备具有两块电池就认定其他驱动采用相同口径。无效读数以缺失表示，各项数据分别判断有效性。

### 容量与健康信息

| 信息类别 | 主要内容 |
| --- | --- |
| 容量 | 剩余容量 `battery_rm`、满充容量 `battery_fcc`、最大化学容量 `batt_qmax`、估计锁容容量、设计容量 `design_capacity` |
| 健康与补偿 | 厂商健康值 `battery_soh`，以及根据设备补偿表反推的原始满充容量、原始健康值 |
| 使用状态 | 循环计数、独立电芯电压与电池温度 |
| 电池资料 | 电量计截止电压、序列号、生产日期及电池类型 |

电池信息页的截止电压读取 `GAUGE_TERM_VOLTAGE` 的实际生效值，容量与健康度补偿反推也使用该值。设备补偿表按电压档位匹配，选择不超过当前电量计截止电压的最高档；说明页提供本机关系表和计算方法。

FCC 表示电量计报告的可用满充容量，Qmax 更接近其估计的最大化学容量。界面显示相关容量与设计容量的比例，便于对照观察。它们都来自电量计和厂商模型，不等同于独立仪器测得的实际容量。

两个原始字段通过补偿关系估算，并非直接读取的内部原始数据。当前实现采用比例反推与整数容量扣除；整数取整、数值封顶及驱动状态可能影响结果。电量计截止电压低于 3.0 V 时不进行这两项反推，计算字段显示缺失，这一显示规则本身不能证明驱动没有补偿。修改截止电压后，容量模型还可能需要充放电过程重新校准。

估计锁容容量使用最大化学容量与当前采用的满充容量的差值，括号内以相对最大化学容量的负百分比表示容量差比例。该值是依据电量计参数计算的估计结果，不代表独立测得的物理容量。

电池信息页采用分层刷新：电压持续更新，容量和温度使用较低刷新频率，其他参数在进入页面时读取。页面显示更新与历史采样计划相互独立。

## 充放电记录

### 记录生命周期与恢复

后台根据外部供电状态建立充电或放电记录，对连接变化进行稳定性确认。每段记录包含起止时间、持续时长、起止容量与电量、采样数据、结束原因，以及对应的耗电或性能统计。

插拔充电、尾充完成、游戏模式切换和记录总开关会按状态划分记录。尾充完成时保存当时读取到的循环计数；删除正在记录的一段后，后台立即按当前状态建立下一段。

应用覆盖更新或系统服务重启后，在内核启动标识、供电状态及记录模式一致时，后台可以恢复同一条活动记录。恢复过程保留已提交数据与统计状态，并在曲线上标记衔接缺口。真正的设备重启或状态变化会按边界重新划分，不补造中断期间的采样。

间隔和持续时间使用单调时钟，日期显示使用系统时间。记录进程通过数据库锁保持单实例运行。

### 充电记录

充电按可配置的秒级间隔保存电流、电压、功率、剩余容量、电量百分比、电芯读数及温度。修改采样间隔沿用当前记录。图表保留原始采样，不进行平滑或显示抽点，便于分析充电阶段、电流波动和温度趋势。

功率由电池侧电压与电流计算，表示电池侧功率。它与充电器输出功率的测量位置不同，不能直接作为充电器或线材标称输出的实测值。

尾充完成由底层满充标记、充电使能、小电流、电压、温度和容量稳定性共同确认，不以系统电量达到 100% 作为唯一结束条件。完成后继续监测，驱动恢复实际充电时可建立后续记录。

### 普通放电记录

普通放电分别配置亮屏、息屏采样间隔，屏幕状态变化触发补读。调整间隔继续使用当前记录，不重新分段。

放电图展示剩余容量、系统电量、电芯电压和区间平均功耗。平均功耗根据相邻采样间的 RM 容量消耗、平均电芯电压与实际经过时间计算，反映整个区间的平均水平。

绘图按时间窗口保留端点、极值和缺口信息，对有效数据使用保形插值。显示曲线的平滑不意味着采样间存在对应的瞬时测量。

不足 10 秒的普通放电区间不参与曲线显示，功耗曲线过滤负值及超过 15 W 的点。过滤点不会替换为零，绘图规则也不删除对应耗电统计。功耗量程根据有效数据确定。

## 游戏模式与性能观察

游戏模式建立独立放电记录，功耗与性能按各自设定的间隔独立采样。调整任一间隔继续使用当前记录，不改变另一项的采样计划。功耗使用电压、电流计算，遵循单双电芯口径，直接绘制原始采样，不使用普通放电的短区间与功耗上限过滤；电池温度随功耗采样间隔记录，并显示在游戏功耗图中。

性能曲线与功耗使用同一段记录的相对时间轴，可对照观察负载、频率、使用率及耗电变化。

| 指标 | 来源与含义 |
| --- | --- |
| 帧率 | 读取 SurfaceFlinger 前台图层的实际呈现时间，表示可取得的画面呈现帧率，不以屏幕刷新率替代 |
| CPU 频率 | 发现 Linux cpufreq 策略组，按实际核心分组读取当前频率，支持不同簇数的处理器 |
| CPU 使用率 | 根据相邻采样的 `/proc/stat` 忙闲计数差，汇总各簇核心的区间利用率 |
| GPU 频率 | 尝试 KGSL、devfreq、GED 等底层接口，读取驱动提供的当前频率 |
| GPU 使用率 | 读取驱动负载百分比或忙闲计数比例，具体统计窗口由驱动决定 |

性能采集使用独立工作线程，缓存硬件节点和图层信息，限制查询等待时间，避免积压尚未完成的任务。详情顶部的 CPU、GPU 当前频率采用单独的轻量读取，不额外触发帧率与使用率采集。不可用的指标保持缺失。

开启或关闭游戏模式会划分记录，接入充电后自动退出，也可启用息屏自动退出。游戏记录不参与自动隐藏和自动删除，支持手动删除。游戏功耗图与性能图分别保存曲线显示偏好。

## 耗电统计与续航预估

### 容量、能量和平均功率

普通放电与游戏模式的应用耗电统计均以 RM 容量变化为基础。普通放电按其采样区间结算；游戏模式使用独立的一分钟周期，在亮灭屏和记录结束时补结算剩余区间。

在容量和电压有效的区间内：

```text
区间容量消耗 = 经回升修正处理后的 RM 下降量
区间能量（Wh）= 容量消耗（mAh）× 区间平均电芯电压（V）÷ 1000
平均功率（W）= 有效区间累计能量（Wh）÷ 有效统计时间（h）
```

RM 能量统计采用平均电芯电压口径，不再叠加双电芯系数。容量回升先累计为修正量，再抵扣后续下降，以减少重复计量。异常跳变、无效电压和过长采样缺口分别影响对应统计的有效性。

游戏模式的瞬时功耗曲线与 RM 区间统计使用不同的测量口径，曲线峰值、应用平均功率与整段容量变化具有不同含义。

### 应用归因与亮息屏总结

后台在结算区间读取系统使用事件，结合应用活动、屏幕和锁屏状态重建前台时间线，再按时长分摊整机容量与能量消耗。应用统计包含使用时长、分摊耗电、占比和平均功率。

短时使用的应用在展示时合并为“其他”；无法确定前台归属、锁屏使用等区间也归入“其他”，息屏时段单独汇总。亮屏和息屏耗电总结从原始统计聚合，平均功率仅使用能量有效的时长，不将缺失读数当作零功耗。

应用耗电是整机消耗在前台时段上的分摊，包含屏幕、系统及后台负载，不是逐进程直接计量。分屏、多窗口和系统事件可用性都会影响归因；当前应用时间线面向主用户，其他用户无法可靠归因的区间计入“其他”。

### 剩余能量与亮屏时长

放电记录页使用当前 RM 容量和电芯平均电压，根据内置的“当前电压—后续平均电压”经验关系估算剩余能量。表内线性插值，表外按边界规则处理，再结合所选记录的亮屏平均功率估算可用亮屏时长。

预估仅在放电记录页可见时周期计算，不保存为历史采样。打开已结束的记录时，剩余能量仍使用当前电池状态，所选记录提供对应的亮屏耗电水平。缺少有效平均功率时不生成时长结果。

关系表不会自动学习每台设备的放电特性。负载、温度、电池老化、校准和关机策略均会影响结果，适合作为相近使用条件下的参考。

## 图表、历史与设置

图表支持指标勾选、时间窗口缩放和平移、数据点查看、实时跟随及横屏全屏。充电图还可展开负方向范围。各类记录独立保存曲线显示偏好。

不同物理量以各自量程归一化到同一时间轴，便于比较趋势；可以切换到所选指标的实际刻度。图表中的相对百分比表示量程位置，只有系统电量曲线本身表示电池电量百分比。

图表为峰值保留显示余量，按数据和指标规则扩展量程。容量遵循独立的基准与自动扩展设置；电压、温度从配置范围扩展；CPU 各簇使用最高频簇的硬件上限作为共同基准，帧率采用分级量程。

历史数据按记录与时间索引查询。充电、游戏功耗与性能数据按原始采样传输，分页用于限制单次传输规模，不改变数据精度。曲线保留缺样和衔接标记，不用连续插值掩盖不可观测区间。

设置集中管理记录总开关、游戏模式、采样间隔、记录保留、首页显示优先项与图表量程。首页优先项决定容量和百分比变化哪一项显示为大字，另一项显示为小字；游戏模式记录的手柄图标固定跟在小字项后。未保存过该优先项时默认显示百分比。停止记录会补读并结算当前段，重新开启建立新段；关闭页面或退出 App 不等于停止记录。

自动隐藏只影响默认列表。自动删除作用于已结束的普通记录，清理已有记录需要另行确认。手动删除会同时移除对应采样、应用统计和性能数据；数据库空闲页可供后续复用，文件不一定立即缩小。

## 截止电压调整

设备具备相应 OPLUS votable 节点时，可在设置页进入截止电压调整，分别查看和设置电量计截止电压、软件关机电压，或解除手动覆盖，交回厂商动态策略。

两项电压可独立设置。实际关机或进入超级省电的时机可能受电量计终止策略、软件低压门限及系统状态共同影响，不能仅凭某一个设置值认定实际触发电压。

调整采用计划与确认提交：校验参数和提交前状态，保存原状态后写入，读回验证，失败时尝试回滚。较低电压需要额外确认电池损伤风险。修改只在明确确认后执行一次，系统重启后可能需要重新设置；安装及常规记录不会自动调整电压。

该功能修改的是驱动参数，不替代电池保护电路，也不能改变电池本身的物理容量。

## 后台运行与本地存储

```text
Android 前台 / 本地 WebView
           │ 持续 su 通信
           ▼
      root 通信桥
           │ 本地套接字
           ▼
      独立记录后台 ── SQLite 数据库
           │
           ├─ 电量计与充电驱动
           ├─ 系统使用事件、显示与电源服务
           └─ CPU / GPU / SurfaceFlinger

root 框架开机入口 ── 启动监督组件 ── 独立记录后台
```

记录进程脱离前台会话运行，由监督组件负责退出后的恢复。开机入口在系统就绪后启动后台，不依赖 Android 应用自启动权限、常驻通知或前台服务。

采样通过原生定时器、电源事件和屏幕状态监听唤醒。前台持续订阅状态及增量数据，页面不可见时暂停对应订阅。内核、驱动和 root 环境决定实际唤醒能力；密集采样与性能采集也会产生监测开销。

应用不申请联网权限，不向远端上传电池状态、应用使用记录或设备信息。界面资源随安装包提供。

| 路径 | 内容 |
| --- | --- |
| `/data/adb/aco_battery_app/` | 配置、识别状态、所有者信息及日志 |
| `/data/adb/aco_battery_app/records.db` | 记录、采样、应用耗电、性能数据及后台配置 |
| `/data/adb/aco_battery_app/runtime/` | 后台程序及运行脚本 |
| `/data/adb/service.d/aco_battery_app.sh` | root 框架开机入口 |

数据库使用 SQLite 事务、WAL 和外键关联。初始化会核对安装用户与签名身份。清除 Android 应用数据不会一并清除独立 root 目录。

系统卸载 APK 后，后台周期检查安装状态，连续确认应用不存在后结束记录、移除启动入口及运行程序，保留历史数据库和配置。查询失败不作为卸载依据；后台未运行时由下次开机检查处理，因此清理存在延迟。重新安装需使用相同签名，才能通过已有目录的身份校验。

应用不提供云同步或图形化备份。手动备份前应停止记录和数据库写入，并正确处理 WAL 状态，不能只复制仍在写入的主数据库文件。

## 安装与构建

从[发布页面](https://github.com/AstriaFR/ACol-Battery/releases/latest)下载安装包，首次打开授予 root 权限并完成初始化。首页查看实时状态和历史记录，电池信息页查看电量计资料，设置页管理记录、采样与电压功能。

源码主要结构：

| 目录 | 职责 |
| --- | --- |
| `src/main/java/` | Android 容器、初始化、root 会话及前台通信 |
| `src/main/assets/webroot/` | 本地界面、图表、设置、电池信息与续航模型 |
| `daemon/src/` | 采样状态机、统计归因、性能采集、后台恢复及原生等待组件 |
| `common/src/` | 共享错误信息处理 |
| `runtime/` | 开机、监督与截止电压操作脚本 |
| `tests/` | 核心计算、记录恢复、时间线及前端数据流回归用例 |
| `tools/` | 编译、打包、签名与字体资源处理 |

构建需要 Python 3、JDK 17、Android SDK 和 NDK。使用 API 37 编译，生成支持 Android 15 及以上的 ARM64 应用与原生组件。

设置 `JAVA_HOME` 与 `ANDROID_HOME` 或 `ANDROID_SDK_ROOT` 后，在源码根目录执行：

```sh
python tools/build.py
```

脚本默认选择 SDK 中已安装的平台、构建工具和 NDK，也可通过 `ACO_ANDROID_PLATFORM`、`ACO_BUILD_TOOLS`、`ANDROID_NDK_HOME` 指定。输出为 `dist/ACol-Battery-v<版本>.apk` 及 SHA-256 校验文件，不自动安装到设备。

默认使用项目内的 `signing/aco.p12` 和 `signing/password.txt` 复用正式签名；也可通过 `ACO_KEYSTORE`、`ACO_KEYSTORE_PASSWORD_FILE` 和可选的 `ACO_KEY_ALIAS` 指定其他签名。密钥文件已被忽略规则排除，不随源码分发。签名材料缺失时构建会停止，不会自动生成新密钥，避免产生无法覆盖升级的安装包。

测试中不依赖 Android 的 Java 用例可在本机运行，前端数据流用例使用 Node.js；系统服务和数据库恢复用例需要 Android 环境或独立适配层。测试工具不属于应用运行依赖。
