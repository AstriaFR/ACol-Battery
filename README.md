# ACol 电池

<img src="src/main/assets/webroot/assets/acol-icon.png" width="88" alt="ACol 电池图标">

**电池信息、充放电曲线记录、耗电统计与预估、使用时间分析、游戏性能观察、截止电压调整。**

ACol 电池是一款使用 root 权限的本地电池监测应用，面向具备兼容 OPLUS 电池接口的 Android 设备。它将底层电池读数、持续充放电记录、应用使用事件和性能指标放在同一套分析界面中，用于观察充电过程、比较使用负载，以及了解电池容量与续航表现。

采集由独立的 root 后台完成，前台负责查看、分析和配置。关闭应用界面不会停止记录；记录、设置和统计缓存保存在设备本地。

[下载应用](https://github.com/AstriaFR/ACol-Battery/releases/latest) · [项目主页](https://github.com/AstriaFR/ACol-Battery)

## 功能概览

| 功能 | 主要内容 |
| --- | --- |
| 实时电池状态 | 电量百分比、剩余容量、电流、电芯电压、电池温度与电池侧功率 |
| 电池信息 | 满充容量、最大化学容量、设计容量、健康度、循环计数、电池资料、容量补偿分析及尾充历史快照 |
| 充放电记录 | 自动划分记录、保存采样、识别尾充、恢复中断的后台记录 |
| 应用耗电分析 | 按使用时间线分摊能量与容量消耗，汇总亮屏、息屏耗电及平均功率 |
| 分时统计 | 在放电记录内查看逐小时耗电与亮屏时长，并查看每小时的应用明细 |
| 使用时间分析 | 独立于充放电记录的日、周、月统计，以及应用的日、周使用情况 |
| 游戏性能统计 | 与普通记录并行，分别采集瞬时功耗与性能数据，对照帧率、CPU/GPU 频率、使用率及温度 |
| 功耗悬浮显示 | 在屏幕顶部持续显示当前电池侧功耗，独立于记录总开关和游戏模式 |
| 截止电压调整 | 读取和分别设置电量计截止电压、软件关机电压，或解除手动覆盖 |
| 数据管理 | 分类与年月筛选、保留策略、错误报告、完整备份恢复及清除数据 |

## 运行要求与兼容性

- Android 15 及以上，ARM64 架构。
- 可向应用授予 root 权限的 `su` 环境，以及能够执行开机脚本的 root 框架。
- 电池记录需要可用的剩余容量、系统电量和外部供电状态接口；暂时缺失时，可进入应用查看受限原因。
- 使用时间分析和应用耗电归因需要系统允许 root 后台读取使用事件；该能力不可用时，电池记录仍可独立运行。

应用通过通用 `su` 入口运行，与 KernelSU、Magisk、APatch 所使用的 `service.d` 开机机制协作，不将 KernelSU 作为唯一入口。实际可用性仍取决于 root 权限、SELinux 策略、内核能力和厂商接口。

电池专有字段、单双电芯识别、容量补偿表及截止电压调整主要面向 OPLUS 接口。ColorOS、realme UI 或相近硬件可以作为兼容性的参考，但系统名称和 Android 版本不能代替接口检查。CPU、GPU 和帧率分别使用自身的系统或驱动接口，缺少某项接口不意味着所有功能都不可用。

首次运行会申请 root、检查接口并部署独立后台。后续打开优先连接已有后台。可选能力不可用时允许降级进入应用，并汇总说明；如果暂时无法取得有效的剩余容量或系统电量，记录保持关闭，可在设置中开启记录时重新读取。

外部供电状态优先从底层电源节点读取，不能可靠判断时，依次尝试 Android 电池广播和 BatteryService 系统状态。各来源都不可用时暂停记录采样并自动重试，不将未知状态猜测为放电。屏幕监听不可用时，尝试广播和周期状态检测。使用事件暂不可用的区间保留为未能归因的统计，后台继续尝试恢复读取。

深度休眠期间能否按时唤醒取决于原生定时器和系统授权。缺少唤醒能力时使用超时等待回退，应用会提示休眠采样受限，不保证休眠中的采样准点完成。

## 电池读数与计量口径

### 数据来源

电压、电流和温度优先解析底层 `bcc_parms` 响应。缺少有效读数时，按字段尝试 Android 电池广播、`BatteryManager` 或相应电源节点，不以一个字段的失败替代其他有效字段。

剩余容量优先使用电量计的 `battery_rm`。不可用时，尝试 `BATTERY_PROPERTY_CHARGE_COUNTER`，完成单位换算后接入容量记录、耗电统计和续航预估。发生回退时，初始化提示及错误报告会说明数据来源。系统电量百分比独立读取。

尚未取得的数据以缺失状态显示。容量、功率、温度等字段分别判断有效性，缺失读数不会作为零值参加计算。

### 单双电芯

后台从厂商数据识别电芯数量并保存结果。识别尚未完成时继续重试，不直接假定为双电芯。

| 电芯结构 | 电压与电流处理 |
| --- | --- |
| 单电芯 | 使用单芯电压，不执行双电芯电流补偿 |
| 双电芯 | 保留可读取的两芯电压，以均压和补偿后的电流计算瞬时功率；当前支持的接口口径下，电流乘以 2 |

双电芯的计算等价于原始电流乘以两芯总电压。系统回退若提供整组电压，会先换算为平均电芯电压；无法取得独立电芯读数时，不伪造两芯数据。

以上补偿针对当前支持的接口格式。不同厂商可能采用不同的电流和容量口径，不能仅凭电池结构相似就认定计算方式相同。

### 电池信息与容量补偿

电池信息页集中展示剩余容量、满充容量 FCC、最大化学容量 Qmax、设计容量、健康度 SOH、循环计数，以及可读取的序列号、生产日期和电池类型。页面还显示容量相对设计容量的比例，便于对照观察。

FCC 更接近电量计报告的可用满充容量，Qmax 更接近其估计的最大化学容量。原始满充容量、原始健康度和估计锁容容量是结合驱动参数计算的参考值，不是独立测量结果。

补偿分析使用 `GAUGE_TERM_VOLTAGE` 的实际生效值和设备提供的补偿关系表。截止电压低于 3.0 V 时不进行补偿反推；达到该范围时按匹配档位计算。说明页提供计算含义与本机关系表。调整截止电压后，电量计模型可能需要后续充放电过程重新校准，不能将刚修改后的字段直接视为准确结果。

电池信息采用分层刷新：电压持续更新，容量与温度降低刷新频率，其他资料在进入页面时读取。页面刷新与历史记录的采样计划相互独立。

### 尾充历史快照

电池信息页提供尾充历史记录，按完成日期与循环计数查看。每次确认尾充完成时，后台保存当时可读取的 Qmax、FCC、SOH、容量补偿结果、设计容量和电量计截止电压，并保留对应的参考值标记。

历史详情展示保存时的数据，不使用当前电池读数重新计算。快照与充放电记录分开保留，支持查看和手动删除；缺失字段保持缺失，不用后续读数补成当时的结果。

## 持续记录与图表

### 记录如何划分

后台根据外部供电状态建立充电或放电记录，并对插拔变化进行稳定性确认。记录包含起止时间、电量与容量变化、采样、结束原因，以及对应的耗电或性能数据。

普通记录在确认插拔充电或尾充完成时结束相应区间。游戏性能统计使用另一条独立记录，开启和关闭只划分游戏记录，不停止普通记录；插拔充电器也不直接结束游戏记录。两类记录共用记录总开关，关闭总开关时补读、结算并结束正在记录的区间，重新开启后建立新段。

手动删除正在进行的记录时，在供电状态可靠且相应记录功能保持开启的情况下，后台立即开始下一段；状态暂不可用时等待自动重试。另一条并行记录继续运行。

应用覆盖更新或系统服务软重启后，同一次内核启动中的活动记录可按已提交的状态继续衔接。普通记录要求充放电状态一致，游戏记录按独立模式恢复，可跨越供电状态变化。恢复使用已提交的采样和统计状态，对中断边界保留标记，不补造丢失的数据。真正的设备重启会结束旧记录并重新划分。

持续时间与采样间隔使用单调时钟，日期使用系统时间。后台通过独占锁避免多个记录实例同时写入。

### 充电记录

充电按可配置的秒级间隔保存电流、电压、功率、剩余容量、电量百分比及电池温度，调整间隔沿用当前记录。

尾充完成由两套独立机制判断，任一满足即可结束充电记录：

1. 厂商日志判定：确认接入充电后尝试读取厂商充电日志，结合满充标记、充电使能、电压条件，以及补偿后电流绝对值小于 50 mA，连续满足 5 分钟。此机制不附加温度、RM 稳定性或系统电量百分比条件。日志不可读或字段缺失时静默跳过该判定，不产生能力检测报错或降级提示。
2. 电压、电流判定：充电连接有效时，电芯平均电压持续大于 4.4 V，补偿后电流绝对值持续小于 50 mA。本次充电尚未读到有效厂商尾充日志时连续确认 5 分钟；读到后改为 10 分钟，后续日志暂时不可读也保持该时长。

两套机制分别计时，不拼接不同条件成立的时段。两者的电流均与界面采用相同的单双电芯补偿口径：双电芯乘以 2，单电芯不放大；单电芯的平均电压即自身电压。第二套机制不依赖厂商满充标记、目标电压、RM、系统电量百分比或温度条件。条件中断、有效读数缺失或采样出现过长缺口时，相关机制重新计时。

确认尾充完成后保存循环计数和电池信息快照，后台继续监测是否发生实际补充充电或拔线。

这里的功率来自电池侧电压与电流，与充电器输出端的测量位置不同，不代表充电器或线材的输出功率。

### 普通放电记录

普通放电分别设置亮屏和息屏采样间隔，屏幕状态变化触发补读。图表展示剩余容量、系统电量、电芯电压、区间平均功耗、电池温度，以及可选的剩余能量估算曲线。

平均功耗来自相邻采样间的容量消耗、平均电芯电压及实际经过时间。普通放电曲线会过滤过短区间和异常功耗点；这些显示限制不会删除原始耗电统计，也不会将被过滤的点画成零值。

### 图表交互

- 按指标勾选显示，并分别记忆充电、普通放电、游戏功耗和性能图的选择。
- 长按指标查看实际量程，支持时间窗口缩放、平移、数据点查看及实时跟随。
- 支持横屏全屏；充电、普通放电与游戏功耗图均可展开负方向范围。
- 放电和游戏功耗图可勾选息屏投影，以已有记录中的息屏时段绘制背景阴影，仅在前台加载和绘制。

不同物理量按各自量程归一化到同一时间轴。图表上的相对百分比表示量程位置，只有系统电量曲线本身表示电池电量百分比。

量程根据指标规则与数据范围扩展。容量和估算能量分别设置默认量程，并共用自动扩展开关；电压、温度以设置范围为基准；电流、功率和性能指标使用相应的分级或峰值策略。图表保留超过标称量程的显示区域，曲线所在的归一化位置与量程是否扩展是两个不同概念。

充电和游戏记录保留逐次采样数据，分页限制单次传输规模；普通放电绘图按视窗选取端点和极值。曲线连接和保形插值用于呈现趋势，不增加测量精度，采样之间的连线不代表该时刻存在实际读数。

## 耗电分析与续航预估

### 容量、能量与功率

普通放电与游戏记录的应用耗电统计都以 RM 容量变化为基础。普通放电按采样区间结算；游戏记录采用独立的分钟结算周期，并在屏幕状态、充放电状态变化及游戏记录结束时补结算剩余区间。游戏记录中的充电区间不分摊应用耗电。

在容量和电压有效的区间内：

```text
容量消耗 = 经容量回升修正后的 RM 下降量
区间能量（Wh）= 容量消耗（mAh）× 区间平均电芯电压（V）÷ 1000
平均功率（W）= 有效区间累计能量（Wh）÷ 有效统计时间（h）
```

容量回升先保留为修正量，再抵扣后续下降，减少重复计量。RM 能量统计使用平均电芯电压口径，不再次叠加双电芯系数。异常容量跳变、无效电压和过长采样缺口影响相应区间的有效性，平均功率只使用能量有效的时间。

游戏功耗曲线由电压、电流计算瞬时值，与 RM 结算的整段容量、能量和应用平均功率属于不同口径。

### 应用归因与分时统计

后台读取系统使用事件，结合活动切换、屏幕和锁屏状态重建前台时间线，再按各时段占比分摊整机消耗。统计以能量展示应用耗电，并提供使用时长、占比、平均功率及容量、电流参考。

短时使用的应用在展示时合并为“其他”。无法确认归属、锁屏使用等区间也归入“其他”，息屏单独汇总。亮屏与息屏总结从原始统计聚合，不受短应用合并方式影响。

普通放电和游戏记录均提供逐小时耗电与亮屏时长视图，可切换日期，在小时明细中查看应用分布。分时耗电使用已结算的 RM 能量，不用瞬时曲线的峰值替代统计；结果按记录和日期缓存。

应用耗电是整机消耗按前台时段进行的分摊，包含屏幕、系统及后台负载，不是逐进程直接测量。分屏、多窗口和系统事件完整性会影响归属。当前使用事件分析面向主用户，其他用户无法可靠归因的区间保留为“其他”。

### 剩余能量与亮屏时长

放电详情根据当前剩余容量和电芯均压，结合内置的电压关系模型估算剩余能量，再使用所选记录的亮屏平均功率估算可用亮屏时长。关系表之间采用插值，超出范围时按边界规则处理。

估算只在放电记录页可见时周期计算，不写入历史采样。查看已结束的记录时，电池状态仍取当前读数，所选记录提供对应的使用负载参考；缺少有效平均功率时不生成时长结果。

剩余能量估算曲线使用同一电压关系模型，根据已有采样点中的容量和电压在前端计算，不增加硬件采集，也不额外保存一组估算采样。默认能量量程未设置或为零时，按可用曲线数据的最大值确定量程。游戏记录中的充电区间不绘制剩余能量估算曲线，游戏详情页的实时剩余能量与亮屏时长预估也只在实际放电时提供。

该模型不会自动学习每台设备的放电曲线，负载、温度、老化、校准和系统关机策略都会影响估算。

## 独立使用时间分析

首页使用时间来自系统 UsageStats 使用事件，不依赖某一段放电记录。前台打开相关页面后，分批补读最近十天内系统仍可提供的事件，按小时统计各应用的亮屏使用时长，包含系统桌面。

- **日视图**：逐小时亮屏时长、每日应用排行，以及指定应用的小时分布。
- **周视图**：按周一至周日汇总，显示总时长、有效日期的日均时长和应用周排行，并可进入某一天或某个应用继续查看。
- **月视图**：按自然月展示每日总时长、总计与日均。

尚未结束的当天不参与日均，缺少可用数据的日期不作为零时长计入平均。已缓存的更早日期可继续查看，但无法保证系统仍保留尚未采集的历史事件。

缓存按日期、小时、应用和每日汇总分层存储，按需读取，不在打开应用时扫描全部历史。周、月概览优先读取每日汇总。有效缓存长期保留在应用数据中；不完整小时可在历史事件仍可读取时分批修补。缺少连续状态时尝试恢复起点前的状态，仍不能确认的时段保持未知。

使用时间分析与放电记录内的时长统计范围不同：前者覆盖系统可提供并已缓存的日期，后者只统计相应记录内的区间。

除当天外，已保存日期的使用时间数据可单独删除。删除范围是该日期的独立使用时间缓存，不会删除对应的充放电记录，也不会清除系统自身的使用历史。

## 游戏性能统计与功耗悬浮显示

### 游戏性能统计

游戏性能统计建立独立的游戏记录，可与普通充电或放电记录同时进行，不限定所运行的应用必须是游戏。放电时，功耗和性能分别使用各自的采样间隔；修改间隔沿用当前记录。充电时，游戏功耗采样跟随充电记录间隔，并在普通充电记录正在采样时复用电池读数，性能采集仍按自己的计划执行。

| 指标 | 读取与统计方式 |
| --- | --- |
| 瞬时功耗、电池温度 | 按功耗采样计划读取电池数据，遵循单双电芯口径 |
| 帧率 | 使用 SurfaceFlinger 前台图层的实际呈现时间，不用屏幕刷新率替代 |
| CPU 频率 | 识别 cpufreq 策略组，按实际核心簇读取频率 |
| CPU 使用率 | 使用相邻采样的 `/proc/stat` 忙闲计数差，汇总各簇核心利用率 |
| GPU 频率与使用率 | 尝试 KGSL、devfreq、GED 等驱动接口，具体统计窗口取决于驱动 |
| CPU/GPU 最高温度 | 从可识别的 CPU、GPU 温度节点中读取最高值 |

性能采集在独立工作线程中执行，复用硬件节点和图层信息，任务未完成时不积压后续采样。记录页顶部的当前 CPU/GPU 频率使用轻量读取，不额外触发完整性能采集。

游戏记录可连续跨越充电和放电，记录中的净电量、净容量变化可以为正或负。功耗曲线以放电为正方向、充电为负方向；应用耗电只结算放电区间，充电量不会抵扣或混入应用消耗。

关闭游戏性能统计或触发持续息屏自动退出时，仅结束游戏记录，普通充放电记录继续运行。游戏记录优先展示于进行中的记录，不受自动隐藏和自动删除策略影响，支持手动删除。

### 功耗悬浮显示

悬浮显示由 root 后台绘制独立显示层，采用电池侧实时电压、电流计算功率，不依赖普通常驻通知。它与游戏模式、历史记录分别控制，开启显示不会开启游戏模式，也不会额外写入历史采样。

刷新节奏跟随游戏功耗采样间隔，息屏时暂停刷新。该功能依赖系统允许 root 创建显示层；缺少相关能力时会报告不可用原因。

### 控制中心开关

应用向系统提供“游戏性能统计”和“功耗悬浮显示”两个控制中心开关，可从系统的备选开关中添加。完成应用初始化且运行文件匹配后，开关通过 root 连接独立后台执行操作，并显示当前可用状态；后台尚未就绪时提示打开应用处理。

## 截止电压调整

设备支持时，可分别查看、设置电量计截止电压和软件关机电压，也可解除手动覆盖，交回厂商策略。

每次操作先生成待确认方案，确认后才写入驱动，并进行读回校验；失败时尝试恢复操作前的值。较低电压设置有额外确认。调整仅在确认后执行一次，系统重启后可能需要重新设置。

两个阈值可以独立设置，但实际关机或进入超级省电仍可能受到电量计截止值及其他系统策略影响。调低阈值不等于增加电池的物理容量，还可能改变电量计报告的 FCC、SOH 和电量估计。

该功能依赖相应的 OPLUS 投票节点，不作为普通记录功能的必需条件。

## 设置、历史与数据管理

首页集中展示实时电池信息、进行中记录和独立使用时间统计；记录页提供全部、充电、普通放电、游戏四类筛选，以及年月筛选。普通放电分类不包含游戏记录。记录卡片以带方向的百分比变化作为主要数值，同时展示起止电量、容量变化、持续时间和结束状态。

记录列表按页读取，滚动到底部继续加载；筛选条数与全部记录数独立统计，不要求先加载全部记录。进行中的记录置于历史记录之前，游戏记录优先于同时进行的普通记录。

设置集中管理记录总开关、功耗悬浮显示、游戏性能统计、采样间隔、量程和保留策略。自动隐藏只影响默认列表；自动删除作用于已结束的普通充电、放电记录，清理已有记录需要额外确认。手动删除会移除关联的采样和统计，SQLite 空闲空间可供后续记录复用，文件不一定立即缩小。

界面支持亮色、暗色和跟随系统的主题设置。恢复默认设置会恢复采样、量程、保留策略及主题，关闭游戏性能统计和功耗悬浮显示，并尝试开启记录总开关；必要电池读数仍不可用时会说明原因。恢复设置不删除已有记录、使用时间缓存或备份。

### 错误报告

应用保存初始化失败、降级及相关错误报告，可在设置中按列表查看详情、复制和清理。报告包含错误原因、实际回退来源及技术信息，降级提示可以退出后继续使用。应用统计等可选服务异常不会单独阻止电池后台启动；未知读数继续保留为缺失或受限状态。

数据库异常时优先保留原文件。重建数据库需要明确确认，并通过系统文件选择器将原数据库文件导出到用户选定的位置；保存及校验完成后才执行重建。该操作与清除所有数据、恢复默认设置分别处理。

### 备份与恢复

应用提供完整数据包备份和覆盖恢复，包括充放电数据库、后台配置、应用设置、使用时间缓存和错误日志。运行程序、签名身份及临时操作状态不作为可恢复业务数据导入。

备份和恢复期间会释放前台数据文件、暂停后台并协调数据库状态。数据包具有格式与完整性校验；恢复使用事务和回滚目录处理覆盖过程。恢复前需要确认，导入的活动记录会结束，再按当前设备状态重新初始化。

“清除所有数据”使用独立的双重确认流程，同时清理应用与独立后台的数据。它与 Android 设置中的“清除应用数据”不同，后者不会自动删除 root 目录中的记录。

## 后台架构与存储

```text
Android 前台与本地 WebView
          │ 持续 su 通信
          ▼
      root 通信桥
          │ 本地套接字
          ▼
      独立采集后台 ── SQLite 记录数据库
          ├─ 电量计与充电驱动
          ├─ 系统使用事件和屏幕状态
          └─ CPU / GPU / SurfaceFlinger

root 框架开机入口 ── 监督组件 ── 独立采集后台
```

后台程序与配置位于 `/data/adb/aco_battery_app/`，记录数据库为其中的 `records.db`，运行文件位于 `runtime/`；开机入口为 `/data/adb/service.d/aco_battery_app.sh`。使用时间等前台缓存位于 Android 应用的私有数据目录。

前台关闭不影响后台所有权。监督组件处理进程退出后的恢复，开机脚本在系统就绪后检查应用身份并启动后台，不依赖普通 Android 自启动权限或前台服务。应用重新打开时使用持续连接和增量数据更新界面。

系统卸载 APK 后，后台周期检查安装状态，连续确认应用不存在才结束记录、清理启动入口和运行文件，历史数据库继续保留。查询失败不当作卸载；后台未运行时由后续开机检查处理，因此不能保证卸载瞬间完成清理。重新安装需要通过已有目录的用户与签名校验。

## 隐私

应用界面和资源随安装包提供，安装清单不申请联网权限。电池读数、应用使用历史、记录、日志和缓存均在本地处理，不向远端上传。项目链接通过系统浏览器打开，备份和恢复通过系统文件选择器访问用户选定的位置。

## 源码与构建

| 目录 | 内容 |
| --- | --- |
| `src/main/java/` | Android 容器、初始化、root 会话、原生页面与数据操作入口 |
| `src/main/assets/webroot/` | 本地界面、图表、设置、使用时间缓存与续航模型 |
| `daemon/src/` | 采样、记录恢复、使用事件归因、性能采集及原生等待组件 |
| `common/src/` | 共享规则、错误报告、数据归档与事务处理 |
| `runtime/` | 开机、监督、数据传输与截止电压操作脚本 |
| `tests/` | 按功能分组的规则、交互与数据安全测试 |
| `tools/` | 构建、签名及资源处理工具 |

构建需要 Python 3、JDK 17、Android SDK 与 NDK，默认使用 API 37 编译。工具链与签名路径通过环境变量或命令参数指定，具体配置见 [构建与资源工具](tools/README.md)。

签名密钥和密码由构建者自行提供，可使用 `ACO_KEYSTORE`、`ACO_KEYSTORE_PASSWORD_FILE` 和可选的 `ACO_KEY_ALIAS` 指定。覆盖安装需要使用一致的签名。

在项目根目录执行：

```sh
python tools/build.py
```

构建产物与 SHA-256 校验文件输出到 `dist/`，脚本不自动安装到设备。测试的功能分组及运行环境见 [tests/README.md](tests/README.md)。
