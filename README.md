# ACol 电池

<img src="src/main/assets/webroot/assets/acol-icon.png" width="88" alt="ACol 电池图标">

**电池信息、充放电曲线记录、耗电统计与预估、截止电压调整。**

ACol 电池是一款面向兼容 OPLUS 电池接口设备的本地电池监测应用，主要适用于 ColorOS 与 realme UI。应用通过 root 读取电量计、充电驱动和系统运行数据，由独立后台持续记录充放电过程，提供电池状态分析、应用耗电分摊和游戏性能观察。

应用将实时读数、历史采样和统计结果分别处理：实时页面反映当前状态，曲线保存过程数据，耗电统计说明一段使用过程中的容量与能量消耗。全部数据保存在设备本地。

[下载安装包与源码](https://github.com/AstriaFR/ACol-Battery/releases/latest)

## 功能概览

| 功能 | 内容 |
| --- | --- |
| 电池信息 | 查看容量、健康度、循环计数、电芯电压、温度及厂商提供的电池资料，分析可用容量与化学容量的关系 |
| 充电记录 | 持续记录充电电流、电压、功率、容量、电量和温度，识别尾充完成并保存循环计数 |
| 普通放电记录 | 按亮屏、息屏状态采样，展示容量、电量、电压与区间平均功耗 |
| 游戏模式 | 按秒记录瞬时功耗、帧率、CPU 各簇及 GPU 的频率和使用率 |
| 耗电分析 | 汇总亮屏、息屏消耗，并按前台使用时段分摊应用耗电 |
| 续航预估 | 根据当前剩余容量、电压关系模型及所选记录的亮屏功耗，估算剩余能量和亮屏时长 |
| 截止电压调整 | 在驱动支持时，读取和调整关机阈值与电量计截止阈值，支持解除覆盖 |
| 历史管理 | 保存独立记录、按类型筛选，并提供自动隐藏、自动删除及手动删除策略 |

## 运行环境与兼容范围

应用要求 Android 15 及以上、ARM64 设备，以及能够向应用提供 root 权限的 KernelSU 环境。初始化会检查 KernelSU 运行组件、电池必要接口、采样定时器和屏幕状态监听能力。

兼容性由底层接口决定。系统需提供 OPLUS 电量计的剩余容量读数，以及系统电池百分比和可识别的外部供电状态。电池详情、独立电芯电压、GPU 指标和截止电压调整各自依赖相应驱动；这些可选字段不一定在所有设备上齐全。相同的系统名称不能保证底层格式和功能完全一致。

首次运行完成 root 授权、接口检查与后台部署。后续打开优先连接已有后台；初始化未通过时，界面显示具体原因。截止电压功能按节点单独判断可用性，不支持时隐藏入口。

## 数据来源与测量口径

### 电池读数

剩余容量来自 OPLUS 电量计的 `battery_rm`，系统电量百分比来自电池电源节点。电压、电流和温度优先解析 `bcc_parms` 响应；缺少有效读数时，分别尝试 Android 电池广播、`BatteryManager` 或系统电源节点，并统一单位和电流方向。

系统接口回退只能提供其实际暴露的数据。设备无法返回独立电芯电压时，应用保留整体电压口径，不生成两个虚构的电芯读数。不可用字段保持缺失；容量、电压与功率也分别判断有效性，不能取得某一项不等于其他读数同时失效。

### 单电芯与双电芯

后台从 `aging_ffc_data` 识别电芯数量并保存识别结果。未能识别时继续重试，依赖电芯数量的电压和功率暂不推算。

| 电芯结构 | 电压口径 | 瞬时电流与功率 |
| --- | --- | --- |
| 单电芯 | 使用该电芯电压 | 使用原始电流，功率为电压与电流的乘积 |
| 双电芯 | 分别保留两芯电压，计算时取平均电压 | 按 OPLUS 电量计口径将电流乘以 2，再与平均电压相乘 |

双电芯公式等价于原始电流乘两芯总电压。若系统回退返回整组电压，程序会先折算到平均电芯电压口径，避免重复计算电芯系数。

这套补偿针对当前实现所支持的 OPLUS 数据格式，不能仅凭设备具有两块电池就推定其他驱动使用相同的电流口径。

### 电池容量与健康信息

电池信息页将电量计容量、健康相关参数和电池身份资料集中展示。

| 信息类别 | 主要内容与来源 |
| --- | --- |
| 容量 | 当前剩余电量 `battery_rm`、满充容量 `battery_fcc`、最大化学容量 `batt_qmax`、设计容量 `design_capacity` |
| 健康 | 厂商健康值 `battery_soh`，以及结合设备补偿参数反推的原始满充容量与原始健康值 |
| 使用状态 | 循环计数、电芯电压、电池温度 |
| 电池资料 | 截止电压 `vbat_uv`、序列号、生产日期与电池类型 |

FCC 更接近电量计报告的可用满充容量，Qmax 更接近其估计的最大化学容量。界面提供两者相对设计容量的比例，以及 FCC 相对 Qmax 的差比例，用于观察可用容量、化学容量与容量限制之间的关系。这些都是电量计和厂商模型给出的指标，不等同于独立仪器测得的实际容量。

原始满充容量与原始健康值依据设备树中的截止电压补偿表反推，说明页可查看本机关系表。无法满足反推条件时保留缺失；截止电压低于 3.0 V 时沿用读取到的 FCC 和 SOH，不执行补偿反推。反推结果仅供参考。

电压在页面可见时持续更新，剩余容量和温度采用较低频率刷新；容量参数、电池资料及补偿关系表在进入页面时读取。页面刷新与历史记录采样相互独立。

## 充放电记录

### 记录生命周期

后台根据外部供电状态建立充电或放电记录，并对连接状态变化进行稳定性确认，减少瞬时波动造成的错误分段。每段记录包含起止时间、持续时长、起止容量与电量、采样数据、记录类型和结束原因。

接入或移除外部供电、确认尾充完成、切换游戏模式、停止记录以及运行中断，均会按照各自状态结束或划分记录。尾充完成的充电记录附带当时读取到的循环计数。删除正在记录的一段时，后台立即以当前状态建立下一段。

时间间隔使用单调时钟计算，显示日期使用系统时间。后台中断后，上一段记录停留在最后已保存的数据处，不把无法观测的时间和容量变化归入下一段。

### 充电记录

充电采用每秒采样，保存电流、电压、功率、剩余容量、电量百分比、独立电芯读数及温度。图表按原始采样绘制，不进行平滑或显示抽点，适合观察电流波动、充电阶段切换和温度变化。

充电功率由电池侧电压、电流计算，表示电池侧功率。它与充电器输出功率的测量位置不同，不能直接用于判断充电器或线材的标称输出。

尾充完成由底层满充标记、充电使能状态、小电流、电压条件、温度和容量稳定性共同确认。系统显示 100% 不是唯一结束条件。完成后进入监测状态，若驱动恢复实际充电，则按状态建立后续充电记录。

### 普通放电记录

普通放电分别设置亮屏和息屏采样间隔，默认亮屏每 2 分钟、息屏每 10 分钟。屏幕状态变化会触发补读，调整间隔不会结束当前记录。

放电图包含剩余容量、系统电量、电芯电压和区间平均功耗。平均功耗由相邻采样之间的 RM 容量消耗、平均电芯电压及实际经过时间计算，反映整个采样区间的平均水平。

普通放电绘图按时间窗口选取端点、极值和缺口信息，并使用保形插值连接有效点。数据库保留采样数据；显示平滑不意味着取得了采样点之间的真实瞬时读数。

普通放电图忽略不足 10 秒的采样区间，功耗曲线也不显示负值或超过 15 W 的点。这些点不会被替换为 0，图表过滤也不删除原始统计。功耗量程由有效数据决定，15 W 是显示过滤阈值。

## 游戏模式与性能分析

游戏模式为短时间负载分析建立独立放电记录。功耗与性能按设定秒数采样，应用耗电另用独立的容量统计周期，避免把高频电流波动与电量计容量变化混为一种测量。

游戏功耗曲线采用补偿后的电流与电芯电压计算瞬时功耗，遵循单双电芯规则。原始秒级数据直接绘制，不使用普通放电的短区间和 15 W 过滤。

性能数据与功耗使用同一段记录的相对时间轴，可对照观察负载、频率、利用率和功耗变化。

| 指标 | 读取与计算方法 | 含义与边界 |
| --- | --- | --- |
| 帧率 | 查询前台图层的 SurfaceFlinger 实际呈现时间 | 反映可取得的画面呈现帧率，不使用屏幕刷新率替代；图层或呈现历史不可用时留空 |
| CPU 频率 | 发现 Linux cpufreq 策略组，读取当前频率 | 同一策略组通常共享频率，按实际核心分组显示，不固定为某一种簇数 |
| CPU 使用率 | 对相邻采样的 `/proc/stat` 忙闲计数求差，再汇总各簇核心 | 表示相邻采样区间的平均利用率，不是单一时刻的利用率 |
| GPU 频率 | 尝试 KGSL、devfreq、GED 等驱动接口 | 表示驱动可提供的当前频率，支持范围取决于设备 |
| GPU 使用率 | 读取驱动负载百分比或忙闲计数比例 | 不同驱动的统计窗口可能不同，不应直接当作统一时间窗口的测量 |

性能采样在独立工作线程中执行，缓存硬件节点和图层信息，对 Binder 查询设置等待上限。上一轮尚未完成时跳过新的采样任务，避免积压过时数据。页面顶部的 CPU、GPU 当前频率使用单独的轻量读取，不额外触发帧率与利用率采集。

开启和关闭游戏模式会划分记录。接入充电后自动退出；可选择息屏一段时间后自动退出。游戏记录不参与自动隐藏和自动删除，仍可手动管理。

## 耗电统计方法

### 容量、能量与平均功率

普通放电和游戏模式的应用耗电统计均以 RM 容量变化为基础。普通放电随其采样区间结算；游戏模式使用独立的一分钟周期，并在亮灭屏和记录结束时结算剩余区间。

在容量和电压有效的区间内，采用以下关系：

```text
区间容量消耗 = 经回升修正处理后的 RM 下降量
区间能量（Wh）= 容量消耗（mAh）× 区间平均电芯电压（V）÷ 1000
平均功率（W）= 有效区间累计能量（Wh）÷ 有效统计时间（h）
```

RM 能量统计使用平均电芯电压口径，不再叠加双电芯系数。电量计容量发生回升时，程序先累计修正，再抵扣后续下降，减少同一容量被反复计算的情况。异常容量跳变、过长采样缺口和无效电压分别影响相应统计的有效性。

游戏模式的瞬时功耗曲线与这里的 RM 区间平均功耗具有不同含义，因此曲线峰值、应用平均功率和整段容量变化不要求逐点一致。

### 应用归因

后台读取系统使用事件，结合应用活动状态、屏幕状态和锁屏状态建立前台时间线，将采样区间切成不同应用与息屏时段，再按时长分摊该区间的容量和能量。

应用统计包括累计使用时长、分摊容量消耗、耗电占比和平均功率。累计使用不超过两分钟的应用在展示时合并为“其他”；无法确定前台归属、锁屏使用等时段也会计入“其他”。息屏时段单独汇总。

亮屏、息屏耗电总结直接聚合原始统计，不依赖短时应用在列表中的合并结果。平均功率只使用能量有效的统计时长，缺失读数不会按零功耗计入平均值。

应用耗电表示整机消耗在前台使用时段上的分摊，包含该时段的系统、屏幕和后台负载，不是逐进程或逐硬件的直接计量。分屏、多窗口、后台任务和系统事件可用性都会影响归因；当前实现的应用时间线面向主用户，其他用户无法可靠归因的区间计入“其他”。

## 剩余能量与续航预估

放电记录页根据当前 RM 容量和电芯平均电压，从内置的“当前电压—后续平均电压”关系表取得剩余放电过程的估计平均电压，计算剩余能量。表内采用线性插值，表外按边界规则处理。

预计亮屏时长由剩余能量除以所选记录的亮屏平均功率得到。没有有效亮屏平均功率时，不生成可用时长结果。

预估只在放电记录页可见时周期计算，不保存为历史采样。即使打开已结束的记录，剩余能量仍来自当前电池状态，所选记录只提供对应的亮屏耗电水平。

关系表是固定的经验模型，不会自动学习每台设备的放电特性。实际负载、温度、电池老化、容量校准与关机策略会影响结果，适合用于相近使用条件下的续航参考。

## 图表与历史分析

充电、普通放电、游戏功耗和游戏性能分别提供曲线选择，并独立保存显示偏好。图表支持时间窗口缩放、平移、数据点查看、实时跟随和横屏全屏，便于同时观察完整过程与局部波动。

不同物理量默认映射到各自量程的相对百分比，以便在同一时间轴比较趋势；实际刻度可按指标切换。这里的百分比表示坐标归一化，仅系统电量曲线本身表示电池电量百分比。

容量、电压和温度以配置量程为基础，按对应规则扩展。性能图按指标设置量程：CPU 各簇使用最高频簇的硬件上限作为共同频率基准，帧率使用分级量程；可变性能量程保留超出基准的显示区间，达到扩展条件后再调整。

图表保留采样缺口与异常标记，不以连续插值覆盖无法观测的区间。充电、游戏功耗和性能数据按原始采样传输，分页用于限制单次查询和传输规模，不改变采样精度。

历史记录按记录和时间索引查询。删除记录会一并移除其采样、应用统计与性能数据；数据库内部空闲页可供后续写入复用，删除不等于数据库文件立即缩小。

## 设置与记录策略

设置集中控制以下策略：

- **记录启停**：总开关决定是否继续采样，停止时补读并结算当前记录，重新开启时建立新记录。
- **记录保留**：自动隐藏仅影响默认列表；自动删除作用于已结束的普通记录，清理已有记录单独确认。
- **采样计划**：分别配置普通放电的亮屏、息屏间隔，以及游戏模式的秒级采样间隔和息屏退出策略。
- **显示量程**：配置容量基准及自动扩展、电压范围、温度范围。

设置由后台校验并保存在本地。记录策略与前台页面的刷新频率独立，关闭页面或退出 App 不等于停止记录。

## 截止电压调整

设备提供相应 OPLUS votable 节点时，应用可读取关机电压与电量计截止电压，分别设置覆盖值，或解除覆盖以恢复驱动策略。

修改采用计划与确认提交两阶段处理。程序检查参数、确认凭据和提交前状态，保存原状态后写入，再读回验证；失败时尝试回滚。安装和常规记录过程不会自动修改截止阈值。

截止电压调整属于底层驱动配置，实际生效方式取决于设备。截止电压通常低于关机电压，应用不建议将相关阈值设置到 2800 mV 以下。该功能不是电池保护电路的替代，也不改变电池本身的物理容量。

## 后台架构与运行机制

应用由 Android 前台、root 通信桥、独立记录后台和启动监督组件组成。

```text
Android 前台 / 本地 WebView
           │ 持续 su 通信
           ▼
      root 通信桥
           │ 本地套接字
           ▼
      独立记录后台 ── SQLite 数据库
           │
           ├─ 电量计与充电驱动
           ├─ 系统使用事件、显示与电源服务
           └─ CPU / GPU / SurfaceFlinger

KernelSU 开机入口 ── 启动监督组件 ── 独立记录后台
```

记录进程脱离前台会话运行，由监督组件负责退出后的重启。KernelSU 开机入口负责在系统就绪后恢复后台，不依赖 Android 应用自启动权限、常驻通知或前台服务。

采样等待使用原生定时器、电源事件和屏幕状态监听，按事件与到期时间唤醒。前台通过持续连接订阅状态和记录增量，不为每次刷新重新启动 root shell；页面不可见时暂停对应展示订阅。

后台监测关键系统服务的 Binder 存活状态。系统服务重启或软重启后，结束原有记录并由监督组件重新连接；设备重启后也重新划分记录。未观测到的中断不补造采样或应用耗电。

root 后台仍受内核、驱动和 root 管理环境约束。若设备不允许休眠唤醒定时器或相关事件接口，实际采样可能出现延迟或缺口。更密集的采样和性能查询也会增加监测本身的开销。

## 本地存储、隐私与卸载

应用不申请联网权限，不向远端上传电池状态、应用使用记录或设备信息。界面资源随安装包提供，记录与配置位于独立 root 目录。

| 路径 | 内容 |
| --- | --- |
| `/data/adb/aco_battery_app/` | 设置、识别状态、所有者信息及运行日志 |
| `/data/adb/aco_battery_app/records.db` | 记录摘要、采样点、应用耗电、性能数据及后台配置 |
| `/data/adb/aco_battery_app/runtime/` | 后台程序与运行脚本 |
| `/data/adb/service.d/aco_battery_app.sh` | KernelSU 开机入口 |

数据库使用 SQLite 事务、WAL 写入日志和外键关联维护记录。应用持有独占后台锁，避免同时启动多个记录进程写入同一数据库；目录同时记录安装用户与签名身份，初始化时校验已有数据的所有者。

清除 Android 应用数据不会一并删除 root 目录。备份历史记录前应先停止记录和数据库写入，再复制所需数据库与配置；不要仅复制仍在写入的主数据库文件而忽略 WAL 状态。应用未提供云同步或图形化备份入口。

系统卸载 APK 后，独立后台不会随前台立刻消失。后台周期检查安装状态，连续确认应用不存在后结算当前记录，删除启动入口和运行程序，保留历史数据库与设置；查询失败不视作卸载。后台未运行时由下次开机检查处理。

因此，卸载清理具有延迟。重新安装时应使用相同签名，才能通过已有 root 目录的身份校验并继续使用保留的数据。

## 安装与使用

1. 从[发布页面](https://github.com/AstriaFR/ACol-Battery/releases/latest)下载安装包。
2. 首次打开时授予 KernelSU root 权限，完成环境检查与后台初始化。
3. 在首页查看当前状态和历史记录，在电池信息页查看容量及健康参数。
4. 按使用目的选择普通记录或游戏模式，并在设置中管理采样和记录保留策略。

历史记录是否持续生成，以设置中的记录总开关为准。必要接口缺失会阻止初始化；可选字段缺失则影响对应数据显示或功能入口。排查运行问题时，可结合初始化提示、记录结束原因和 root 目录中的运行日志判断。

## 源码结构与构建

| 目录 | 职责 |
| --- | --- |
| `src/main/java/` | Android 容器、初始化、root 会话及前台通信 |
| `src/main/assets/webroot/` | 本地页面、图表、设置、电池信息及续航模型 |
| `daemon/src/` | 电池采样、记录状态机、耗电归因、性能采集、进程监督与原生等待组件 |
| `common/src/` | 共享错误信息处理 |
| `runtime/` | 开机、后台监督与截止电压操作脚本 |
| `tests/` | 独立统计规则与系统服务恢复相关测试 |
| `tools/` | 编译、签名、打包及字体资源处理工具 |

构建需要 Python 3、JDK 17、Android SDK 和 NDK。项目使用 API 37 编译，生成面向 Android 15 及以上的 ARM64 应用与原生组件；编译平台要求与应用最低运行系统不同。

配置 `JAVA_HOME` 与 `ANDROID_HOME` 或 `ANDROID_SDK_ROOT` 后，在源码根目录运行：

```sh
python tools/build.py
```

脚本默认从 SDK 目录选择已安装的平台、构建工具和 NDK，也可通过 `ACO_ANDROID_PLATFORM`、`ACO_BUILD_TOOLS`、`ANDROID_NDK_HOME` 指定路径。构建产物为 `dist/ACol-Battery.apk`，同时生成 SHA-256 校验文件，不自动连接或安装到设备。

未指定签名时，构建脚本创建并复用本地签名材料。使用已有签名可配置 `ACO_KEYSTORE`、`ACO_KEYSTORE_PASSWORD_FILE`，必要时指定 `ACO_KEY_ALIAS`。私钥和密码不随源码分发；自行签名的安装包不能直接覆盖其他签名的应用，也不能绕过保留数据的签名校验。
